Grid keyboard cell navigation, after the APG treegrid pattern, for both the SVG and the Canvas renderer. It exists only when `withGrid` is composed: without it every key behaves exactly as before.

Beta: the chart stays ONE Tab stop (the active row) and gains three modes. ROW mode (a row has focus): Right on a collapsed parent expands it; Right on an expanded parent or a leaf enters the first cell; Left on an expanded parent collapses it; Left on a collapsed parent or a leaf moves to the parent row and selects it (on a top-level leaf nothing happens; the key is still claimed, like Right, so the container does not scroll sideways); Ctrl/Cmd+Home and Ctrl/Cmd+End go to the first and last row. CELL mode (a `gridcell` has focus): Left/Right/Home/End move between the cells of the row (clamped, no wrap), Up/Down/PageUp/PageDown/Ctrl+Home/Ctrl+End move between rows and keep the column, Escape or Left from the first cell returns to the row, and Up on the first row goes to that column's header. HEADER mode (from G3): Left/Right/Home/End between the headers, Alt+Left/Right resizes, Down returns to the cell the header was entered from (or to the first row when it was entered from the row), Escape to the row. Left and Right swap under RTL (the physical key order flips, the logical meaning does not). A cell is script-focusable only (`tabindex="-1"`), and Tab or Shift+Tab from a cell or a header first puts the focus on the roving row and then runs the default, so the chart is one Tab stop in both directions.

Everything else is deliberately NOT claimed and reaches `keyboard-nav` exactly as from a row, also from a focused cell: Alt+Arrow and Alt+Shift+Arrow (move and resize the task) and Alt+Enter (link), Space, Delete/Backspace (still deletes the selected tasks, NOT "clear cell"), `g`/`G`, Shift+Arrow, Enter (a parent still toggles), F2, undo/redo/duplicate/zoom. Enter and F2 are reserved for the editing PR. A key during IME composition, typed in an `input`, `textarea`, `select` or `contenteditable` inside the chart, with Ctrl/Cmd or Shift where the grid does not own the combination, or already default-prevented by an earlier handler, is ignored. Which keys the grid claims is decided synchronously; the actions run from a lazy chunk (the same one as the column resize code), so the very first key may act a moment late. Claimed keys that arrive before it loads are applied in order, each re-checked against where focus is by then (a key the new mode would not claim is dropped); unclaimed keys still act at once. If the chunk cannot be fetched (warned once, retried on the next focus) the claimed keys do nothing. Ctrl+Home/End are forwarded to `keyboard-nav` as an untrusted bare Home/End that stops at the chart container, so host document listeners never see it. A host that bound its own bare Left/Right/Ctrl+Home/Ctrl+End on the chart sees the grid claim them in the capture phase when `withGrid` is composed.

Focus: the focused cell shows a 2 px ring inset in the cell next to the row's focus frame (SVG: one sticky element in the chart layer, created only while a cell has focus; Canvas: painted on the label canvas), in the token colour (`Highlight` in forced colors on the SVG ring and the row frame; the Canvas ring is not forced-colors aware, as the G3 header frame). The SVG ring is drawn under the pinned date axis, so it never covers it. Focus survives a repaint (a host `updateTask`, a zoom, a selection change): the SVG chart puts it back on the cell, the Canvas renderer re-focuses the same cell after rebuilding its accessibility layer. Each cell is a real `gridcell` with `aria-colindex`, so a screen reader announces the row, the column header and the value; no container carries an `aria-label`, and the bar keeps its accessible name.

Beta: `GridOptions.resizable: false` no longer takes the header keyboard mode with it. The headers stay script-focusable and navigable (ArrowUp from the first row, Left/Right/Home/End); only the resizing (drag handles, Alt+Left/Right, `resizeGridColumn`) is off. The doc comment on `resizable` says so. WCAG: keyboard access is 2.1.1 (Keyboard); this PR makes no 2.5.7 claim.

Canvas renderer (lazy chunk, `CanvasGridPainter` is internal): a focused cell survives the hidden accessibility layer's rebuild instead of handing focus to the row, the bar ring is not painted while a cell has focus, and `paintCell` draws the ring.

Known limits: Alt+Left/Right still moves the task from a cell (that is the point), so moving across cells is Left/Right only. On Canvas, a cell focused by assistive technology on a row other than the roving row is restored on the roving row. Without `withInteraction`, Left to the parent focuses the parent row directly. Type-to-edit and editing are a later PR.

Bundle cost (gzip): hello world +0 B, `+ withRender + withInteraction` +0 B, kitchen sink +0 B, `+ withRender + withGrid` +192 B (soft) and the everything gate +164 B (38631 -> 38795), inside the 41.5 KiB limit, which is therefore not raised. The key actions, the cell ring and the Canvas ring are lazy (the `grid/resize-ui` chunk grows from about 1.7 KiB to 2.5 KiB gzip, fetched on first use; `grid/canvas-grid` grows with `paintCell`).
