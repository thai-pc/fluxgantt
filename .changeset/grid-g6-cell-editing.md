New opt-in mixin `withGridEditing` on the subpath `@fluxgantt/core/grid-editing`: inline cell editors for the grid. Apply it after `withGrid` (it throws otherwise). Nothing changes for a chart that does not compose it: the bundle of every other composition is as before, and the editor code is a lazy chunk fetched when a cell first takes focus or is first edited.

Beta: `withGridEditing(instance, { isEditable?, beforeCommit?, activate?, commitOnBlur? })` adds `startCellEdit(taskId, columnId)`, `cancelCellEdit()` and `isEditingCell()`, and the event `cell:edit-requested` (`@beta`, cancellable: `preventDefault()` opens your own editor instead). Enter on a focused cell, F2 (on a row it edits the name cell), and a double-click or double-tap on a pinned cell open the editor; Enter or Tab commits, Escape cancels, and blur commits a valid value (an invalid one is discarded and announced). Editors: `name` is text, `start` and `end` are native date fields, `duration` is a decimal in the column's unit (a text field with a numeric keyboard, not `type=number`), `progress` is a percent. A custom column opts in with `editor: { type: 'text' | 'number' | 'date', commit(input, task, ctx), maxLength?, min?, max?, initial? }`; its `commit` may return only `name`, `start`, `end`, `duration` and `progress` (each validated like the built-in editor of that field; any other key, such as `meta`, `color` or `parent`, is rejected and nothing is written, so build editors for other fields on `cell:edit-requested`), and a built-in column can opt out with `editor: false`. A summary's rolled-up cells, a milestone's end and duration, and every cell of a `readOnly` chart are not editable, and `cell:edit-requested` does not fire for them.

Each edit is ONE store write (`updateTask`, `resizeTask` or `setProgress`): one undo entry and one `task:updated`, with the auto-scheduling cascade grouped into it. A start date keeps the bar's working duration (weekends, holidays, lunch windows and DST in the calendar's zone) and snaps forward to a working day; an end date snaps back to one and must stay after the start; a value that changes nothing writes nothing. Validation is inline: an invalid value sets `aria-invalid` and shows its message in a `role="alert"` element, and the editor stays open on Enter. The input is named by the new `messages.gridEditLabel`, the messages come from `messages.gridEditError`, and results are announced through the live region `withInteraction` owns, as the new `GanttAnnouncement` kinds `cell-edited` and `cell-edit-failed` (silent without `withInteraction`; focus returning to the cell makes the screen reader read the new value). User text reaches the DOM only as text, is length-checked, stripped of control and bidi characters and parsed before it is written, and a custom `commit` result cannot overwrite `id`, the timestamps or the prototype.

Keyboard behaviour: when `withGridEditing` is composed, Enter, F2 and a double-click or double-tap on an editable cell open the editor INSTEAD of `keyboard-nav`'s collapse toggle and `withEditHooks`' `task:activated`; on a cell that is not editable (and in charts without the mixin) all of them behave exactly as before. Moving to another window or tab commits the open editor, as a blur does (`commitOnBlur: false` discards it). The editor lives outside every row element. A column resize, `collapseBelow` or `setGridColumns` repaint, removing the edited task and an import close the editor without a write. WCAG 2.1.1 (keyboard) and 3.3.1 (error identification); a cell gets `aria-readonly="true"` when it takes focus and is not editable.

Limits: no type-to-edit, no range copy and paste, no select or user-picker editors (build those on `cell:edit-requested`). The first key after a cell takes focus may act a moment late while the editor chunk loads. On Canvas, opening an editor from a focused cell and closing it again no longer repaint the chart (the renderer treats focus handed to the editor host as staying in the grid and skips a focus paint that shows nothing new). `updateTask` writes a patch and records its history entry before it validates dates and emits, so a write can throw after it landed; the editor then undoes exactly that one entry (and says it is saved, not "not saved", if it cannot). A `startCellEdit` call made inside a command (for example from a listener) opens the editor a microtask later, after the host's veto is known. The duration editor accepts up to ten years (3650 days, or 87600 hours) and a name up to 500 characters (the core import cap).

Bundle cost (gzip): hello world +0 B, `+ withRender + withInteraction` +0 B, kitchen sink +0 B, `+ withRender + withGrid` +156 B (soft, the editor option and the grid seam), the everything gate +1027 B (39051 -> 40078, now composing `withGridEditing`), inside the 41.5 KiB limit, which is not raised. The editor chunk (`grid-editing/editing-ui`, lazy) is in no budget. The new soft fixture `+ withRender + withInteraction + withGrid + withGridEditing` is 29336 B.
