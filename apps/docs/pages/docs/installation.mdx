# Installation

:::warning
**Pre-release — not on npm yet.** FluxGantt's packages are at `0.1.0` in-repo and not yet
published, while the tiers and API stabilize pre-1.0. The `pnpm add` commands below are the target
end-state. Until the first npm release, run FluxGantt **from source**
(see [Run from source](#run-from-source)).
:::

## Packages

| Package | Install when you want… |
|---|---|
| `@fluxgantt/core` | The headless engine + SVG renderer (vanilla JS/TS). |
| `@fluxgantt/react` | A `<FluxGantt>` React component + `useFluxGantt` hook. |
| `@fluxgantt/vue` | A `<FluxGantt>` Vue 3 component + `useFluxGantt` composable. |

The wrappers depend on `@fluxgantt/core` — you do not install it separately when using a
wrapper, but you may still import types/helpers (e.g. `toTaskId`) from it.

## Once published

```bash
# Core only (vanilla)
pnpm add @fluxgantt/core

# React
pnpm add @fluxgantt/react

# Vue
pnpm add @fluxgantt/vue
```

npm / yarn work too (`npm install @fluxgantt/core`, `yarn add @fluxgantt/core`).

### Peer dependency: Temporal

FluxGantt does all date math with the [Temporal API](https://tc39.es/proposal-temporal/). It
is exposed as an **optional** peer dependency, `@js-temporal/polyfill`. Install the polyfill
unless your runtime already ships Temporal natively:

```bash
pnpm add @js-temporal/polyfill
```

"Optional" applies to the **runtime** only. Core bundles no polyfill code — it reads
`globalThis.Temporal` — so a runtime that has Temporal natively needs no install to *run*. The
published type declarations are a separate matter: they name `Temporal.ZonedDateTime` by
importing the type from `@js-temporal/polyfill`, so if you compile with `skipLibCheck: false`
and the package is absent, TypeScript reports `TS2307` against our `.d.ts`. Install it as a
devDependency in that case.

Why not avoid the import? Both alternatives were measured and are worse. `temporal-spec` (the
types-only package) declares `Duration.round` with different overloads, so a real polyfill
`PlainDate` is *not assignable* to a `temporal-spec` `PlainDate` — consumers would get `TS2345`
at the call site, which is louder than a lib-check warning. And the TS 6 built-in global via
`/// <reference lib="esnext.temporal" />` works on TypeScript 6 but `lib.esnext.temporal.d.ts`
ships in no 5.x release (verified absent from 5.7.3 and 5.9.3), so it would break every
TypeScript 5 consumer outright. We will drop the import once native `Temporal` is in the
DOM/ES lib baseline that our supported TypeScript range covers.

React and Vue peer versions: React `^18.2 || ^19`, Vue `^3.4`.

## Run from source

Because nothing is on npm yet, the supported way to try FluxGantt today is from a clone. The
example apps depend on the workspace packages via `workspace:*`, so `pnpm install` links them
with no registry involved:

```bash
git clone https://github.com/thai-pc/fluxgantt
cd fluxgantt
pnpm install
pnpm build                          # build @fluxgantt/core + wrappers

# then run any example:
pnpm --filter plain-html-demo dev   # vanilla core
pnpm --filter react-vite-demo dev   # React
pnpm --filter vue-vite-demo dev     # Vue
```

Requirements: Node ≥ 22.19 (see `.nvmrc` for the exact pinned version), pnpm 10+.
