# Drag & Drop

Compose `withInteraction` and FluxGantt wires three drag gestures into every `mount()`
automatically — unless the instance is [`readOnly`](/docs/interactions/read-only). You don't
call anything per gesture; the mixin plus mounting is enough:

```ts
import { createGantt } from '@fluxgantt/core';
import { withRender } from '@fluxgantt/core/render';
import { withInteraction } from '@fluxgantt/core/interaction';

const gantt = withInteraction(withRender(createGantt({ tasks: [/* … */] })));
gantt.mount(document.getElementById('gantt')!);
```

Interaction is opt-in so a consumer who only needs a static painted chart (a report, a
thumbnail, a print view) never downloads the gesture recognizers. Apply both mixins **before**
the first `mount()` call — hooks are read at mount time, so composing `withInteraction` onto an
already-mounted instance takes effect only on the next mount.

## The three gestures

| Gesture | What it does | Event emitted |
|---|---|---|
| **Move** — drag a task bar horizontally | Reschedules the task, preserving its duration | `task:moved` |
| **Resize** — drag a bar's start/end edge handle | Changes the task's duration | `task:resized` |
| **Create dependency** — drag from a task's link handle onto another task | Adds an `FS` dependency | `dependency:added` |

Gesture priority is resolved automatically: an edge-handle claim wins over a whole-bar claim,
and a link-handle claim wins over an edge zone — so the three never fight over the same pointer.

## Canvas mode (2,000+ tasks)

All three gestures work in the Canvas renderer too, with the same snapping (whole calendar days),
the same events and the same undo behaviour. A few things look different, because a Canvas chart
is one bitmap rather than a tree of elements:

- **Ghost preview.** While you drag, the original bar stays painted and a translucent copy
  follows the pointer on an overlay layer; the chart itself is not repainted until you drop.
  Escape cancels with nothing to undo.
- **Link handles** are drawn on that overlay for the bar under the mouse and for selected bars.
  On a touch screen, tap a bar first to select it: its handles appear and can then be dragged.
- **Hover cursors**: `grab` over a bar, `ew-resize` over its right edge, `crosshair` over a handle.
- **Touch** works under [`withResponsive`](/docs/api#responsive): a finger on a bar drags it,
  a finger on empty chart area still pans.
- There is no auto-scroll near the edges (SVG has none either), and Ctrl+wheel zoom is still
  SVG-only.

## Keyboard shortcuts

`withInteraction` also wires keyboard navigation and the shortcut set below. Nothing here needs
configuring — mounting is enough — and every binding calls the same facade method you could call
yourself, so the events and undo behaviour are identical either way.

| Keys | Action | Method | Gated by `readOnly` |
|---|---|---|---|
| <kbd>Tab</kbd> | Move focus into the chart — one stop for the whole grid (WAI-ARIA APG grid pattern), not one per row | — | no |
| <kbd>↑</kbd> / <kbd>↓</kbd> | Move focus one row **and** select it, replacing the previous selection. No wraparound at either end | `select` | no |
| <kbd>Shift</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd> | Extend the selection from the anchor row | `select` | no |
| <kbd>Home</kbd> / <kbd>End</kbd> | Move focus to the first / last visible row and select it. With <kbd>Shift</kbd>, extend the selection from the anchor row | `select` | no |
| <kbd>PageUp</kbd> / <kbd>PageDown</kbd> | Move focus one page of rows (the container height, minus one row of overlap), clamped at both ends. With <kbd>Shift</kbd>, extend the selection | `select` | no |
| <kbd>g</kbd> | Scroll the focused row's bar into view horizontally (<kbd>G</kbd> works too). Needs [`withViewport`](/docs/api#viewport-zoom); moves neither focus nor selection | `scrollToTask` | no |
| <kbd>Space</kbd> | Toggle the focused row's selection | `select` / `deselect` | no |
| <kbd>Enter</kbd> | Collapse/expand the focused row. On a leaf: nothing, unless [`withEditHooks`](/docs/api#edit-hooks) is applied, which then emits `task:activated` | `toggleCollapse` | no |
| <kbd>F2</kbd> | With `withEditHooks`: emit `task:activated` for the focused row (summary rows too, where <kbd>Enter</kbd> still collapses) | — | no |
| <kbd>ContextMenu</kbd> / <kbd>Shift</kbd>+<kbd>F10</kbd> | With `withEditHooks`: emit `task:context-requested` for the focused row | — | no |
| <kbd>Delete</kbd> / <kbd>Backspace</kbd> | Remove the selection, as one undo step | `removeTask` | **yes** |
| <kbd>Ctrl/Cmd</kbd>+<kbd>Z</kbd> | Undo | `undo` | **yes** |
| <kbd>Ctrl/Cmd</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> | Redo | `redo` | **yes** |
| <kbd>Ctrl/Cmd</kbd>+<kbd>D</kbd> | Duplicate the selection | `duplicateTask` | **yes** |
| <kbd>Ctrl/Cmd</kbd>+<kbd>+</kbd> / <kbd>=</kbd> | Zoom in one level | `zoomIn` | no |
| <kbd>Ctrl/Cmd</kbd>+<kbd>−</kbd> | Zoom out one level | `zoomOut` | no |
| <kbd>Ctrl</kbd>+wheel | Zoom (anywhere over the chart container, the pinned header included). Also how a macOS trackpad pinch arrives | `zoomIn` / `zoomOut` | no |
| <kbd>Click</kbd> | Select a row (plus its descendants) | `select` | no |
| <kbd>Ctrl/Cmd</kbd>+click | Add/remove one row from the selection | `select` | no |
| <kbd>Shift</kbd>+click | Select the range from the anchor row | `select` | no |

- **<kbd>↑</kbd>/<kbd>↓</kbd> scroll vertically only**, so stepping through rows never moves the
  timeline sideways. <kbd>g</kbd> is the explicit "go to bar". In the SVG renderer the row label sits
  in the pinned label column, so the focused row stays visible even when its bar is off-screen.
- **<kbd>PageUp</kbd>/<kbd>PageDown</kbd> assume the chart's own scroll container.** They page by the
  container's height, so give the container a fixed height with `overflow: auto`; in an auto-height
  container that the page scrolls instead, a "page" is the whole chart.
- <kbd>Home</kbd>/<kbd>End</kbd> always mean first/last **row**. Cell-level Home/End is not offered
  because the grid has no cells.

Two things worth knowing before you bind your own handlers on top:

- **The zoom and undo/redo shortcuts call `preventDefault()`**, because
  <kbd>Ctrl/Cmd</kbd>+<kbd>+</kbd>/<kbd>−</kbd> is the browser's own page zoom and
  <kbd>Ctrl/Cmd</kbd>+<kbd>D</kbd> is "bookmark this page" — without it both the chart and the
  browser would react to one keystroke. A plain wheel event is never intercepted, so the
  container's own scrolling is untouched.
- **<kbd>Ctrl/Cmd</kbd>+<kbd>D</kbd> is not always suppressible.** Some browsers (notably
  Firefox in some configurations) don't let a page cancel that reserved shortcut, so the
  bookmark dialog may still appear alongside the duplicate. That is a known, accepted v1 gap.

There is deliberately no <kbd>Ctrl/Cmd</kbd>+<kbd>A</kbd> binding — "select all" in an embedded
widget would fight the host page's own text selection. Call `selectAll()` from your own handler
if you want it.

In `readOnly` mode the gated rows above become inert **without** calling `preventDefault()` —
the keystroke passes through to the host page rather than being swallowed. Focus, selection,
collapse and zoom all keep working, because none of them mutate data.

## Keyboard alternative to dragging

Every drag gesture has a keyboard equivalent (WCAG 2.2 SC 2.5.7, Dragging Movements). They act on
the **focused row only**, even if several rows are selected (drag moves one bar too), go through the
same commit path as the pointer (same events, same cascade, same undo), and are inert under
`readOnly` (`enableDependencyDrag: false` also turns off linking).

| Keys | Action | Mirrors |
|---|---|---|
| <kbd>Alt</kbd>+<kbd>→</kbd> / <kbd>←</kbd> | Move the task one calendar day later / earlier | drag-move |
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>→</kbd> / <kbd>←</kbd> | Lengthen / shorten the task by moving its end one day (never shorter than one day, or than the task already is) | drag-resize |
| <kbd>Shift</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd> to the target row, then <kbd>Alt</kbd>+<kbd>Enter</kbd> | Link the row where the Shift range began (source) to the focused row (target), finish-to-start | drag-create-dependency |

- Holding the key repeats, one day per tick, and **each press is its own undo step**. Auto-repeat
  fires about 30 times a second, so a few seconds of holding fills the history limit (`historyLimit`,
  default 100) and evicts older undo entries. Tap the key for single steps.
- Resizing steps past weekends and holidays: one press changes the working-hours duration, so a
  task ending on a Friday ends on the next working day afterwards.
- Left/right are **logical** on the time axis: in an [RTL chart](/docs/rtl) later dates are visually
  on the left, so <kbd>Alt</kbd>+<kbd>←</kbd> moves the task later there.
- Only the end edge is resizable, exactly like dragging (the start edge never moves).
- Rolled-up summary bars (when `rollup` is configured) and milestone resizes are declined, as in drag.
- The bar is scrolled back into view after a move or resize (needs `withViewport`, as for <kbd>g</kbd>).
- <kbd>Alt</kbd>+<kbd>←</kbd>/<kbd>→</kbd> is "Back / Forward" in Chrome, Edge and Firefox on
  Windows and Linux; the chart calls `preventDefault()` on it. <kbd>Ctrl/Cmd</kbd>+<kbd>Alt</kbd>+arrow
  is left alone (tab switching, screen readers).
- On Windows, <kbd>Alt</kbd>+<kbd>Shift</kbd> is the default shortcut for switching input
  language, so users with several keyboard layouts may see the layout flip on the resize keys.
- On macOS <kbd>Option</kbd> is <kbd>Alt</kbd>. <kbd>Option</kbd>+letter types a symbol, which is why
  every binding here is an arrow or <kbd>Enter</kbd>.
- The rows between the source and the target stay **selected**, so a <kbd>Delete</kbd> pressed right
  after linking removes all of them. Press <kbd>↑</kbd>/<kbd>↓</kbd> once to collapse the selection.
- A source row hidden by a collapse is not linked from.
- Results are announced to screen readers through a polite live region (moved / resized with the new
  start and end including times, linked, "link not created"). Translate or reword them with
  `messages.announce`, which receives a `GanttAnnouncement`. Pointer drags are not announced; hosts
  that want that listen to `task:moved` / `task:resized`, which carry no keyboard-versus-pointer flag.
- Invalid links (to itself, a duplicate, or one that would create a cycle) are dropped silently,
  exactly like a rejected drop. Listen for `dependency:added` to confirm.

See also [read-only charts](/docs/interactions/read-only).

## Listening to the results

Every gesture commits through the same pipeline as the programmatic API, so the events carry
the same payloads:

```ts
gantt.on('task:moved', (task, prevStart) => {
  // task is the updated Task; prevStart is where it started (a DateInput)
  console.log(`${task.name}: ${prevStart} → ${task.start}`);
});

gantt.on('task:resized', (task, prevDuration) => {
  // prevDuration is the previous duration in working hours
  console.log(`${task.name} resized (was ${prevDuration}h)`);
});

gantt.on('dependency:added', (dependency) => {
  console.log(`linked ${dependency.from} → ${dependency.to} (${dependency.type})`);
});
```

Each `on(...)` returns an unsubscribe function:

```ts
const off = gantt.on('task:moved', handler);
off(); // stop listening
```

## The same operations, programmatically

The drag gestures are just interactive wrappers over methods you can also call directly:

```ts
gantt.moveTask(id, '2026-08-06');                       // ≡ drag-move
gantt.resizeTask(id, 24);                                // ≡ drag-resize (24 working hours)
gantt.linkTasks(fromId, toId, 'FS');                     // ≡ drag-create-dependency
```

## Cascade on drag (opt-in)

By default a move/resize affects only the dragged task (`schedulingMode: 'manual'`). Set
`schedulingMode: 'auto'` at construction to have dependent tasks pushed along their FS/SS/FF/SF
links (+lag) when you drag — each shifted task emits its own `task:moved`:

```ts
const gantt = withInteraction(
  withRender(createGantt({ tasks: [/* … */], dependencies: [/* … */], schedulingMode: 'auto' })),
);
```

## Invalid drops are silently reverted

Dragging out a dependency that would be a self-link, a duplicate, or a cycle is rejected — the
gesture simply snaps back, with no error thrown into the page and no event emitted.

## With the pinned label column

In SVG mode the label column is pinned (`position: sticky`) over the chart. A bar scrolled under it
is covered, so you can only grab its visible part, a press on the column never starts a drag, and a
dependency drag released over the column creates nothing. `scrollToTask(id, { align: 'start' })`
parks the bar directly right of the column. See the
[`withViewport` notes](/docs/api) for the full pinning model.
