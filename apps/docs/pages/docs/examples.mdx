Every example below is in the repo: **six vanilla-TypeScript pages, a React app, a Vue app, and a
headless script that needs no app at all.** Four of them open on StackBlitz with no install
(the first boot takes 1-4 minutes while StackBlitz clones the repo, installs dependencies and
downloads Rolldown's WebAssembly build):

The StackBlitz projects are generated from the **latest npm release**: at release time,
`tooling/scripts/build-stackblitz-examples.mjs` copies the examples to the repo's `stackblitz`
branch with `workspace:*` replaced by the published versions. The copies under `examples/` track
`master` and may use API that is not released yet; run those from a clone (below).

:::note
**Not live yet.** The `stackblitz` branch is written by the release workflow, and the first
release that runs it has not happened yet, so until then these links return a 404. Run the examples

Spec §9.1 sets the Wave 1 target at "10+ live examples on StackBlitz". These are **4 StackBlitz
projects** (the six vanilla pages share one project); the remaining examples are the Pro/Cloud demos
listed at the bottom.

## Running any of them

```bash
git clone https://github.com/thai-pc/fluxgantt
cd fluxgantt && pnpm install && pnpm build
```

Then start the app that hosts the example you want.

[StackBlitz](https://stackblitz.com/github/thai-pc/fluxgantt/tree/stackblitz/vanilla?file=src%2Fmain.ts&title=FluxGantt%20vanilla)
they are one project: append `/read-only.html`, `/selection.html` and so on to the preview URL.

| Page | Shows | Source |
|---|---|---|

| `/read-only.html` | `readOnly: true` — every drag affordance inert, the chart still fully keyboard-navigable ([Read-only mode](/docs/interactions/read-only)) | [`src/read-only.ts`](https://github.com/thai-pc/fluxgantt/blob/master/examples/plain-html-demo/src/read-only.ts) |

The `?pad=` and `?collapsed=` query parameters on `/collapse.html` exist because these pages double
as the Playwright fixture host — which is the useful part for you too: every page here is covered by
e2e, visual and a11y tests, so none of them can rot silently.

## Headless — no example app needed

The engine has no DOM dependency, so this is the whole example:

```ts
import { Temporal } from '@js-temporal/polyfill';
import { createGantt, toTaskId } from '@fluxgantt/core';

// Node 22/24 have no native Temporal; core reads globalThis.Temporal (no-op where it is native).
(globalThis as unknown as { Temporal?: typeof Temporal }).Temporal ??= Temporal;

const gantt = createGantt({
  tasks: [
    { id: toTaskId('design'), name: 'Design', start: '2026-08-03', end: '2026-08-05', progress: 1, type: 'task' },
    { id: toTaskId('build'), name: 'Build', start: '2026-08-05', end: '2026-08-10', progress: 0, type: 'task' },
  ],
  dependencies: [{ from: toTaskId('design'), to: toTaskId('build'), type: 'FS' }],
});

const { criticalTaskIds, projectEnd } = gantt.computeCriticalPath();
```

Run it with `node`, in a Worker, in a Lambda, or in a test with no jsdom. The two Temporal lines are
needed wherever the runtime has no native Temporal, which includes current Node (see
[Installation](/docs/installation)). [Open the headless example on StackBlitz](https://stackblitz.com/github/thai-pc/fluxgantt/tree/stackblitz/headless?file=index.mjs&title=FluxGantt%20headless)
to run it in the browser; its source is `tooling/stackblitz-templates/headless/` in the repo. At **{/*sz:hello.2*/}7.50{/*/sz*/} KiB gzip** this
configuration ships no renderer at all — see [Comparison](/docs/comparison).
